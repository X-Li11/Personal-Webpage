# Microservices Configuration & Scan Guide
The below is the whole road map if you are running YARR scans through Microservices with FELIX+Opto and through **runkey**. See [this section](#test-process) for the Testing Process on felix3 through container command line way.
 
## 1. Configuration Checklist

Before using the DAQ system, verify the following configuration files.

### FELIX Configuration

**File**
```
stacks/felix/config/felix_config.json
```

Verify that the **RX** and **TX** links are correct (contain links needed).

- In principle, the default configuration is already correct.
- No changes should be needed.

---

### Optoboard Configuration

**File**
```
stacks/optoboard/opto-ui-config/ConfigGUI.json
```

Verify the following values (Felix group? and device used):

```text
flx_G = 0
flx_d = 0
```

These should match the values used in the old:

```
/daq/alias.sh
```

---

### Connectivity File

Verify that the following values match the local hardware setup.

Current configuration:

```text
RX    = 0, 4, 8
regRx = 1, 5, 9
TX    = 0
```

---

## 2. Running Scans via Microservices

### Git Repository

Repository:

https://gitlab.cern.ch/demi/itkpix/release.git

Use:

```
v1.0.0-epsilon
```

This version is currently more reliable than the `main` branch, as it has been tested by other groups for running MHT/PFA scans through the Runkey Manager UI.

Directory layout:

```text
release-epsilon:
/home/atlas/microservices/release-epsilon/

main branch:
/home/atlas/microservices/release/
```

Unless otherwise noted, all paths below are relative to:

```text
/home/atlas/microservices/release-epsilon/
```

---

### Enable FELIX Register Writing

In the controller files under:

```
stacks/yarr/config/
```

Manually enable:

```json
"WriteFelixRegsOnLoad": true
```

---

## 3. Start the Dashboard

Run:

```bash
./config
```

If prompted (only once for a fresh copy), enter:

```text
slac
ItkTestBox
```

Then start all containers:

```bash
docker compose up -d
```

To stop everything:

```bash
docker compose down
```

---

## 4. Assemble the Runkey

Open the **Assembler UI**.

### Create a Pseudo-LLS

For a single module, use:

```
daq-manager-example/scripts/setup_hardware.py
```

Notes:

- Change the LLS name in the last line if the version changes, otherwise the upload will fail.
- In the future this step will be replaced by loading the LLS from the PDB.
- The current script has already been modified for the triplet module in the thermal chamber.
- Generally, only the `modules=[]` section needs to be edited.

Run:

```bash
uv run setup_hardware.py
```

A new LLS should then appear in ConfigDB.

For more complicated detector structures, use:

```
setup_lls.py
```

and modify:

```
lls_config.py
```

---

### Upload FE Chip Configurations

FE chip configurations can either:

- be uploaded automatically during LLS creation (toggle in the script), or
- be uploaded manually through the **FE-Config Import** tab.

---

### Upload Connectivity & Controller Files

Use the **Connectivity Import** tab.

#### Connectivity File

- Connectivity files are LLS-dependent.
- Example files are located under:

```
daq-manager-examples/
```

- The connectivity file for the single triplet thermal chamber setup is located at:

```
stacks/yarr/configs/modules/20UPIM04202209_TESTONWAFER
```

#### Controller Files

Located under:

```
stacks/yarr/configs/controller
```

There are additional tweaks available in the `main` branch controller files that experts suggested may improve behavior, although they have not yet been fully tested.

Upload each file using the appropriate file type in the dropdown menu, then click **Submit**.

A new tag should appear on the right-hand side after a successful upload.

---

### Configure Scan Assembly

In the **Scan Assembly** tab:

- Select the scans to include.
- **Important:** choose **models.daq** rather than **emulator** to run on real hardware.

---

### Build the Runkey

In the **Runkey Assembly** tab:

- Select the desired scan tags.
- Select the FE configuration tags.
- Build the runkey.

---

## 5. Configure FELIX & Optoboard

These steps can be performed before or in parallel with the runkey assembly.

### Power On the Optoboard

Power supply settings:

- Mode: **Constant Voltage**
- Voltage: **2.5 V**
- Current limit: **1.5 A**

---

### FELIX UI

Start the following services:

```text
felix-toflx
felix-tohost
felix-register
```

Use:

```text
flx-info
```

to verify link alignment.

---

### Optoboard UI

Click:

```
Configure all Optoboards
```

This performs the initialization.

Expected result:

- **4 links aligned**

---

## 6. Run the Scan

### Power On the Module

Power supply settings:

- Mode: **Constant Current**
- Current: **5.5 A**
- Voltage limit: **3 V**

---

### Runkey Manager UI

1. Select the desired runkey from the left dropdown.
2. Click **Apply Runkey**.
3. The scan will begin.

---

### Task Tab

The **Task** tab displays the running services.

Useful information includes:

- which DAQ instance is executing the scan,
- current scan status,
- progress of individual services.
